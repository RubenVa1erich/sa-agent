# Статус проекта

**Вход:** `trace.md`, `outputs/` (шапки артефактов), `project_context.md`.
**Выход:** сводка в сообщении. Файл — только если просят:
`outputs/reviews/<project_id>_status_<ГГГГ-ММ-ДД>.md`.

Скилл **только читает**. Найденные расхождения — предлагает исправить, но не правит без согласия.

## Алгоритм

1. **Собери данные:**
   - `trace.md` целиком
   - список файлов `outputs/**` (Glob), для каждого `.md` — шапка (версия, статус, дата, источники)
   - Grep по `outputs/` — все ID (`БТ-`, `ФТ-`, `НФТ-`, `ОГР-`, `ОВ-`, `ТК-`, `ADR-`) с файлами
2. **Покрытие** (по строкам trace):
   - БТ без СТ
   - ФТ без спецификации / без тестов
   - ФТ с API-взаимодействием, но без контракта (если из текста требования видно, что есть вызов)
   - ТК, ссылающиеся на несуществующие или устаревшие ФТ
3. **Свежесть.** Артефакт устарел, если в его «Источниках» указана версия, а есть новее
   (тесты по `spec_v1`, а уже есть `spec_v2`; `.confluence.md` отстаёт от исходника).
4. **Целостность trace:**
   - ID в документах, которых нет в trace, и наоборот
   - Счётчики меньше максимального фактического номера; дубли номеров
   - Требования «Устарело», на которые ещё ссылаются действующие артефакты
5. **Открытые вопросы:** количество по адресатам; блокирующие — с указанием, что блокируют;
   самые старые (по дате артефакта, где появились).
6. **Готовность** (если спросили «готовы ли к передаче»): Must-ФТ без AC, без тестов,
   с блокирующими ОВ или в документах со статусом «Черновик» — это стоп-факторы.

## Формат

```
📊 <project_id> — статус на ГГГГ-ММ-ДД

Артефакты: N (спеки X, API Y, диаграммы Z, тесты W, ADR V)
Требования: БТ N · ФТ N · НФТ N · Устарело N

Покрытие
  БТ → СТ:       N/M  (не покрыты: БТ-004)
  ФТ → тесты:    N/M  (без тестов: ФТ-012, ФТ-015)
  ФТ → контракт: …

⚠️ Требует внимания
  1. tests_v1 построены по spec_v1, актуальна spec_v2 — обновить тесты
  2. ФТ-021 есть в spec_v2, но нет в trace.md
  3. Счётчик ФТ = 18, в документах есть ФТ-020

❓ Открытые вопросы: N (блокирующих K)
  PM: 3 (блокирует: ФТ-012)
  Архитектор: 1
  Без адресата: 2

Готовность к разработке: <да / нет — стоп-факторы списком>   ← только если спрашивали

Дальше: <1–2 действия с наибольшей отдачей>
```

Показывай только непустые блоки. Если trace пуст или артефактов нет — скажи это одной
строкой и предложи первый шаг вместо пустой сводки.

**Excel** («в Excel», «матрицу трассировки для PM»): через `anthropic-skills:xlsx` →
`outputs/reviews/<project_id>_trace_<ГГГГ-ММ-ДД>.xlsx`. Листы: «Трассировка» (строки `trace.md`
как есть, с автофильтром), «Покрытие» (цифры из блока «Покрытие»), «Открытые вопросы»
(ОВ | вопрос | адресат | блокирует | где). Только выгрузка — правки делаются в `trace.md`.

Для PM-версии («статус для PM»): без ID в основном тексте, в терминах фич и рисков,
5–7 строк; ID — в скобках, если без них непонятно.

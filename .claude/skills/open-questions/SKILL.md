# Открытые вопросы

**Источник истины:** таблица «Открытые вопросы (сводно)» в `trace.md`.
В артефактах вопросы живут в разделах «Открытые вопросы», как `[TODO: ...]` и как
`> ⚠️ Допущение`. Задача скилла — чтобы ответ, полученный один раз, дошёл до всех мест.

Малый артефакт — сразу результат, но **изменения в документах — только после подтверждения**.

## Режим 1. Закрыть вопрос ответом

1. **Найди вопрос.** Если номер назван — Grep `ОВ-007` по `trace.md` и `outputs/`.
   Если номера нет («PM сказал, что отзыв доступен до принятия оффера») — найди
   подходящие ОВ / TODO / допущения по смыслу и покажи кандидатов; при неоднозначности —
   один вопрос «Это ответ на ОВ-004 или ОВ-009?».
2. **Найди все места влияния** — не только строки с `ОВ-007`, но и связанные `[TODO]`
   и допущения в тех же артефактах про то же самое (Grep по ключевым словам вопроса).
3. **Классифицируй ответ** для каждого места:
   - ✅ **Подтверждает допущение** — допущение превращается в утверждение, пометка снимается
   - ✏️ **Заполняет пробел** — TODO заменяется значением
   - 🔄 **Опровергает допущение / меняет требование или контракт** — существенное изменение
   - ➕ **Порождает новое** — новое требование, новый вопрос, решение для ADR
4. **Покажи план** таблицей и жди подтверждения (если аналитик уже сказал «правь сразу» /
   «подтверждение не нужно» — покажи план в итоговом сообщении и применяй без ожидания):

   | Артефакт | Место | Было | Станет | Тип |
   |---|---|---|---|---|

   Под таблицей — что ещё предлагаешь (ADR, `impact-analysis`, новые ОВ).
5. **Примени:**
   - `trace.md`: статус ОВ → «Закрыт», колонки «Ответ» (кратко + кто ответил) и «Закрыт» (дата).
   - Документы — версия:
     - **Аналитик прямо сказал, в какой версии править** («правь в текущей», «делай v3») —
       так и делай, для любого типа изменения, включая 🔄. Его указание важнее правила
       по умолчанию: он знает, отдан ли документ команде. Изменение всё равно запиши строкой
       в «Истории изменений» той же версии («v2, ГГГГ-ММ-ДД: закрыт ОВ-007, …»).
     - **Указания нет:** ✅/✏️ в неотданном черновике — текущая версия; 🔄 или документ уже
       отдан команде — новая `_v<N+1>` по правилам `artifacts.md`. Если неочевидно, отдан ли
       документ, — спроси одним вопросом «Правлю v2 или делаю v3?».
     - В «Истории изменений» — «Закрыт ОВ-007: …».
   - В разделе «Открытые вопросы» документа строка не удаляется — помечается
     «Закрыт ГГГГ-ММ-ДД: <ответ>», чтобы ревьюеры видели, что изменилось.
   - 🔄 затрагивает API, модель данных или другие компоненты → предложи `impact-analysis`.
   - Ответ — архитектурное решение → предложи `decision-log`.
6. Сообщение по формату `artifacts.md` + список изменённых файлов.

Ответ частичный («таймаут — да, 30 с; про retry спросим у банка») → закрой то, что закрыто,
а остаток оформи новым ОВ со ссылкой на исходный (статус старого — «Закрыт частично → ОВ-015»).

## Режим 2. Добавить вопрос

«Добавь вопрос к архитектору: …» → номер по правилу «Как выдавать номера» (`conventions.md`),
строка в `trace.md` (вопрос, артефакт, кому, «Открыт»). Если вопрос относится к конкретному
документу — предложи добавить его и туда.

## Режим 3. Список вопросов к встрече

«Что спросить у PM?», «вопросы к банку на завтра»:

1. Отбери открытые ОВ с этим адресатом (и без адресата — отдельным блоком «Кому — не определено»).
2. Сначала **блокирующие** (что именно блокируют: ФТ, контракт, релиз), затем остальные.
3. Каждый вопрос — переформулируй так, чтобы на него можно было ответить на встрече:
   конкретно, с вариантами ответа, если они очевидны, без внутренних ID в тексте.
4. Выдай в сообщении готовым к копированию списком; ID — в скобках в конце строки, чтобы
   потом закрыть ответы по ним. В файл не сохраняй, если не просят.

## Режим 4. Сверка

«Сверь вопросы», а также как часть `project-status`:
- ОВ, которые есть в артефактах, но нет в `trace.md` → добавить в trace
- ОВ «Открыт» в trace, но помечены закрытыми в документе (или наоборот)
- `[TODO]` в артефактах без соответствующего ОВ → предложить завести ОВ
Изменения — после подтверждения.

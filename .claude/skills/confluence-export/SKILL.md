# Экспорт для Confluence Cloud

**Вход:** готовый `.md`-артефакт.
**Выход:** рядом файл с тем же именем и расширением `.confluence.md`.

Редактор Confluence Cloud конвертирует Markdown при вставке, но не всё. Цель — файл,
который вставляется «как есть» без ручной правки.

## Как вставлять (сказать аналитику один раз, при первом экспорте)

Открыть `.confluence.md` в редакторе/IDE → выделить всё → скопировать → вставить в
страницу Confluence Cloud в режиме редактирования. Заголовки, таблицы, списки, код
преобразуются автоматически. Диаграммы — см. ниже.

## Преобразования

| В исходном .md | В .confluence.md |
|---|---|
| Шапка-таблица без заголовка (`\| \| \|`) | Таблица с заголовками `Параметр \| Значение` (Confluence плохо вставляет пустые заголовки) |
| `# Заголовок` документа | убрать — это название страницы; указать его первой строкой комментария `<!-- Название страницы: ... -->` |
| Блоки ```plantuml | оставить код, перед блоком строку: `> 📊 Диаграмма: вставьте макрос PlantUML (или /plantuml) и перенесите код ниже. Файл: outputs/diagrams/<file>.puml` |
| `> ⚠️ Допущение: ...` | `> ⚠️ **Допущение:** ...` (цитата вставляется как quote; при желании — сменить на панель Warning) |
| `[TODO: ...]` | `**[TODO: ...]**` — жирным, чтобы было видно на странице |
| Ссылки на локальные файлы `outputs/...` | оставить текстом в `код`, без ссылки (в Confluence они битые) |
| Вложенные списки глубже 2 уровней | упростить до 2 уровней |
| HTML-теги, сноски, чекбоксы `- [ ]` | заменить на обычный текст / список |
| Эмодзи 🔴🟡🟢 | оставить (Confluence Cloud поддерживает) |
| Большие YAML/proto | не встраивать целиком: «Контракт: `<file>` — приложить файлом к странице» + ключевые фрагменты |

## В конце файла

```markdown
---
_Сгенерировано из `<путь к исходному .md>` (v<N>). Источник истины — исходный файл;
при изменении обновите страницу из новой версии._
```

## Правило синхронизации

`.confluence.md` всегда соответствует той же версии, что и исходник. При создании
`_v<N+1>` исходника — создаётся и новая Confluence-версия.

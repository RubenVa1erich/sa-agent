# Создание проекта

## Алгоритм

1. **project_id.** Латиница `[a-z0-9_-]`, начинается с буквы, коротко. Если аналитик назвал
   проект по-русски — предложи транслитерацию/сокращение и согласуй.
   Проверь, что `projects/<project_id>/` не существует.
2. **Источник контекста.** Спроси одним вопросом: «Есть описание системы в файле, или
   заполним по ходу?» Если есть файлы — прочитай их и заполни шаблон сам.
   Если нет — создай шаблон с `[TODO]`, заполнив то, что уже известно из разговора.
   Не устраивай анкету: контекст дозаполняется по мере работы.
3. **Создай структуру:**
   ```
   projects/<project_id>/
     project_context.md    ← из templates/project_context.md
     trace.md              ← из templates/trace.md
     inputs/.gitkeep
     outputs/{requirements,specs,api,diagrams,integrations,impact,reviews,decisions,tests,data,meetings}/.gitkeep
   ```
4. Сообщи, что создано, какие ключевые поля контекста пустые (язык, соглашения API,
   нумерация — если отличаются от умолчаний), и что файлы для анализа кладутся в `inputs/`.

## Обновление контекста

По ходу работы всплывают факты о системе (новый компонент, соглашение, ограничение).
В конце задачи, если такие факты появились — предложи: «Добавить в project_context: <список>?»
и после согласия дополни файл. Не редактируй контекст молча.

## Шаблоны

- `templates/project_context.md`
- `templates/trace.md`

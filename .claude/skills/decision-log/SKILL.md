# Журнал решений (ADR, MADR)

**Вход:** описание ситуации и решения (часто — сумбурный пересказ встречи).
**Выход:** `outputs/decisions/NNNN-ГГГГ-ММ-ДД-<kebab-case-название>.md`. Малый артефакт — сразу результат.

## Алгоритм

1. Определи номер по правилу «Как выдавать номера» (`conventions.md`): счётчик `ADR` в
   `trace.md`, сверенный с именами файлов в `outputs/decisions/`.
2. Из пересказа извлеки: проблему/контекст, драйверы решения, варианты, выбранный вариант,
   аргументы, последствия, участников, дату.
3. **Не выдумывай** рассмотренные варианты и аргументы, которых не было. Если аналитик
   назвал только решение — варианты: `[TODO: какие альтернативы обсуждали?]`.
   Можешь *предложить* очевидные альтернативы отдельным блоком «Возможно, стоит упомянуть»
   в сообщении (не в ADR), чтобы аналитик выбрал.
4. Статус по умолчанию — **Принято**, если аналитик говорит «решили»; **Предложено** — если «думаем», «предлагаю».
5. Если решение заменяет предыдущее — у старого ADR поменяй статус на
   «Заменено [ADR-MMMM](...)», в новом — «Заменяет ADR-NNNN». Это единственный случай
   правки существующего ADR.
6. Обнови счётчик ADR в `trace.md`. Если решение влияет на существующие артефакты —
   перечисли их в «Последствиях» и предложи `impact-analysis`.

## Шаблон (MADR)

```markdown
# ADR-NNNN. <Краткое название решения>

| | |
|---|---|
| Статус | Предложено / Принято / Отклонено / Устарело / Заменено ADR-MMMM |
| Дата | ГГГГ-ММ-ДД |
| Участники | <кто принимал> |
| Проект | <project_id> |
| Связано | <ФТ-ID, CR, другие ADR, спеки> |

## Контекст и проблема

<2–5 предложений: какая ситуация, какой вопрос нужно было решить.>

## Драйверы решения

- <требование / ограничение / качество, которые определили выбор>

## Рассмотренные варианты

1. <Вариант A>
2. <Вариант B>
3. <Вариант C>

## Решение

Выбран вариант «<A>», потому что <главное обоснование>.

### Последствия

- 👍 Хорошо: ...
- 👎 Плохо / компромисс: ...
- Требуется: <изменения в артефактах, задачи, договорённости>

## Плюсы и минусы вариантов

### <Вариант A>
- 👍 ...
- 👎 ...

### <Вариант B>
- 👍 ...
- 👎 ...

## Дополнительно

<Ссылки, условия пересмотра решения («пересмотреть, если нагрузка > N RPS»).>
```

## Список решений

По запросу «какие решения принимали» — прочитай заголовки и статусы из `outputs/decisions/`
и выдай таблицу: ADR | дата | название | статус. Отфильтруй по теме, если спросили про конкретную.

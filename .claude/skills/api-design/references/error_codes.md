# Коды ошибок

## HTTP — когда какой

| HTTP | Когда | `code` (пример) | Retry клиентом |
|---|---|---|---|
| 400 | Синтаксис / схема / формат полей невалидны | `VALIDATION_ERROR` (+ `errors[]`) | нет |
| 401 | Нет / невалиден / истёк токен | `UNAUTHORIZED` | после обновления токена |
| 403 | Аутентифицирован, но нет прав на операцию / объект | `FORBIDDEN` | нет |
| 404 | Ресурс не найден (или скрываем существование от неавторизованного) | `<ENTITY>_NOT_FOUND` | нет |
| 405 | Метод не поддерживается | — | нет |
| 409 | Конфликт состояния: дубликат, неверный статус для перехода, гонка | `<ENTITY>_ALREADY_EXISTS`, `INVALID_STATE_TRANSITION` | нет (или после перечитывания) |
| 412 | `If-Match` не совпал (оптимистическая блокировка) | `PRECONDITION_FAILED` | после перечитывания |
| 415 | Неподдерживаемый Content-Type | — | нет |
| 422 | Запрос валиден синтаксически, но нарушает бизнес-правило | `LIMIT_EXCEEDED`, `INSUFFICIENT_FUNDS` | нет |
| 429 | Превышен лимит запросов | `RATE_LIMITED` (+ `Retry-After`) | да, после `Retry-After` |
| 500 | Непредвиденная ошибка сервера | `INTERNAL_ERROR` | да, с backoff (для идемпотентных) |
| 502 | Ошибка вышестоящей системы | `UPSTREAM_ERROR` | да, с backoff |
| 503 | Сервис временно недоступен / обслуживание | `SERVICE_UNAVAILABLE` (+ `Retry-After`) | да |
| 504 | Таймаут вышестоящей системы | `UPSTREAM_TIMEOUT` | да — **только с Idempotency-Key**, результат неизвестен |

### Частые ошибки дизайна
- 200 с `{"success": false}` — нет. Ошибка → 4xx/5xx.
- 400 на бизнес-правила — лучше 422, чтобы отличать от ошибок формата.
- 500 на «не найдено во внешней системе» — это 404/422 или 502, в зависимости от смысла.
- 504 без описания, что делать клиенту: результат операции *неизвестен* — нужна
  идемпотентность или эндпоинт проверки статуса.

## Каталог кодов в спецификации

Для каждого сервиса — таблица всех `code` (машиночитаемых), чтобы фронт/потребители
могли их обрабатывать:

| code | HTTP | Сообщение (title) | Когда | Действие клиента |
|---|---|---|---|---|

`code` — `UPPER_SNAKE_CASE`, стабилен (часть контракта; переименование — ломающее изменение).

## События — обработка ошибок консьюмером

| Класс ошибки | Пример | Действие |
|---|---|---|
| Временная | БД/зависимость недоступна | retry с backoff (N попыток) → DLQ |
| Постоянная | невалидный payload, неизвестная версия | сразу DLQ + алерт, не блокировать партицию |
| Бизнес-отказ | событие неприменимо к текущему состоянию | лог + игнор / компенсирующее событие (описать) |
| Дубль | повторная доставка | дедупликация по `id`, ack без обработки |

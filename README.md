# SA Agent — помощник системного аналитика

Агент для Claude Code, который делает черновую работу системного аналитика: декомпозицию
требований, ФТ/ТЗ, API-контракты, диаграммы, интеграционные спецификации, анализ влияния,
ревью спек, ADR и тест-кейсы. Цель — структура и ~70% содержания; решения и финальная
доводка остаются за аналитиком.

Агент не привязан к домену и компании: всё специфичное живёт в `project_context.md` проекта.

## Быстрый старт

```bash
git clone <URL репозитория> sa-agent
cd sa-agent
claude
```

При старте агент показывает список проектов и новые входные файлы.

1. **Новый проект:** «Новый проект: платёжный шлюз» → агент согласует `project_id`,
   создаст `projects/<id>/` и шаблон `project_context.md`.
2. **Заполни контекст** (`projects/<id>/project_context.md`) — хотя бы архитектуру и
   отличия соглашений от умолчаний. Можно дописывать по ходу.
3. **Положи материалы** в `projects/<id>/inputs/` (txt, md, docx, pdf).
4. **Попроси:** «demo_loans: декомпозируй inputs/task-early-cancel.txt».

Попробовать сразу — в `projects/demo_loans/` лежит демо-проект с заполненным контекстом и задачей.

## Что умеет

| Запрос | Скилл | Результат |
|---|---|---|
| «Декомпозируй задачу» | `requirements-decompose` | ФТ/НФТ/ограничения, edge cases, конфликты, открытые вопросы |
| «Напиши ТЗ / ФТ» | `spec-write` | Документ по шаблону (default / api_focused / свой) |
| «Спроектируй API» | `api-design` | OpenAPI 3.1 / AsyncAPI 3.0 (Kafka, RabbitMQ) / proto3 / прочее + замечания по дизайну |
| «Нарисуй sequence / ERD / C4 / статусы» | `diagram-generate` | PlantUML + описание |
| «Опиши интеграцию с X» | `integration-spec` | Спецификация + sequence (основной и сбойный) + маппинг |
| «Пришёл CR, что затронет?» | `impact-analysis` | Отчёт: затронутое, классификация 🔴🟡🟢, артефакты к обновлению, план |
| «Проверь спеку» | `quality-review` | Таблица проблем с серьёзностью и рекомендациями |
| «Зафиксируй решение» | `decision-log` | ADR в формате MADR |
| «Тест-кейсы» | `test-cases` | Позитивные/негативные/граничные кейсы с трассировкой |
| «Сделай для Confluence» | `confluence-export` | `.confluence.md` для вставки в Confluence Cloud |
| «Спроектируй таблицы / миграцию» | `data-model` | Сущности, поля, индексы, ПДн, ERD, DDL, план миграции без простоя |
| «ОВ-007: ответ …» / «что спросить у PM?» | `open-questions` | Закрытие вопроса во всех артефактах, список вопросов к встрече, сверка |
| «Вот заметки со встречи» | `meeting-digest` | Дайджест: решения, ответы, новые требования и вопросы + действия по артефактам |
| «Что по проекту?» | `project-status` | Покрытие, устаревшие артефакты, рассинхрон trace, открытые вопросы, готовность |

Скиллы также можно вызвать напрямую: `/api-design`, `/quality-review` и т.д.

**Дополнительно:**

| Запрос | Как работает |
|---|---|
| «Прожарь задачу» / «допроси меня» | `requirements-decompose` в режиме прожарки: серии вопросов, потом декомпозиция |
| «Сделай версию для Word» | `.docx` из готового `.md` (внешний скилл `anthropic-skills:docx`) |
| «Выгрузи кейсы в Excel / для TestRail» | `.xlsx` / `.csv` из тест-кейсов (`anthropic-skills:xlsx`) |
| «Матрицу трассировки в Excel» | `project-status` → `.xlsx` (`anthropic-skills:xlsx`) |
| Модель данных / миграция | `data-model` дополнительно сверяется с `supabase-postgres-best-practices` |

## Внешние скиллы

Подключены только как шаги цепочек (список и правила — CLAUDE.md → «Внешние скиллы»).

- `anthropic-skills:docx`, `anthropic-skills:xlsx` — встроены в Claude, ставить не нужно.
  При первом запуске могут доустановить пакеты Python / Node.
- `supabase-postgres-best-practices` — установлен в `.claude/skills/`, источник и хэш — в
  `skills-lock.json`. Обновление: `npx skills update -p` из папки агента.
- Новый внешний скилл ставить **в проект, без `-g`**:
  `npx skills add <owner/repo> --skill <имя> -a claude-code --copy`, затем добавить строку в
  CLAUDE.md → «Внешние скиллы» и прогнать `evals/`.

## Как агент работает

- На неполный запрос задаёт **1–2 вопроса**, остальное — явные допущения (`⚠️ Допущение`).
- Для **крупных** артефактов (ТЗ, API-сервис, интеграция, крупный CR, декомпозиция БТ на 3+
  компонента) сначала показывает структуру. «Без согласования» — пропустить этот шаг.
- Не ставит пакеты и программы без спроса.
- Не выдумывает детали: `[TODO: уточнить — …]` + раздел «Открытые вопросы».
- Перед выдачей проверяет артефакт по чек-листу качества.
- Не принимает архитектурных решений молча — предлагает варианты.

## Структура

```
sa-agent/
  CLAUDE.md                  # роль, выбор скилла, принципы
  README.md
  .claude/
    settings.json            # разрешения + SessionStart-хук
    hooks/session_start.sh   # список проектов при старте
    rules/                   # поведение, артефакты, соглашения, планка качества
    skills/<скилл>/SKILL.md  # 15 своих скиллов + templates/ и references/
                             # + supabase-postgres-best-practices (внешний)
  skills-lock.json           # источники внешних скиллов
  tools/extract_docx.py      # текст из .docx
  projects/<project_id>/
    project_context.md       # контекст проекта — главное, что стоит заполнить
    trace.md                 # матрица трассировки БТ → ФТ → API → тесты
    inputs/                  # твои материалы
    outputs/                 # артефакты агента по типам
```

## Артефакты

- Имя: `<project_id>_<объект>_<тип>_v<N>.<ext>`. Новая версия — новый файл, старые не перезаписываются.
- Крупные документы — сразу в двух видах: `.md` и `.confluence.md`.
- Как вставить в Confluence Cloud: открыть `.confluence.md`, скопировать всё, вставить в
  редактор страницы. Диаграммы — через макрос PlantUML (код в `outputs/diagrams/`).
- Диаграммы смотреть: плагин PlantUML для VS Code / IntelliJ (с локальным рендером через
  `plantuml.jar` или локальный PlantUML server в Docker). **Не вставлять** код в публичный
  plantuml.com — диаграмма уходит на чужой сервер вместе с архитектурой работодателя.
  В плагине VS Code проверь настройку `plantuml.render`: должно быть `Local`, а не `PlantUMLServer`
  с адресом plantuml.com.

## Настройка под себя

| Что | Где |
|---|---|
| Соглашения конкретного проекта | `projects/<id>/project_context.md` → «Соглашения команды» |
| Умолчания для всех проектов (API-стиль, нумерация) | `.claude/rules/conventions.md` |
| Свой шаблон ТЗ | положить в `.claude/skills/spec-write/templates/` и указать в project_context |
| Чек-лист качества | `.claude/rules/quality_bar.md`, `.claude/skills/quality-review/references/quality_criteria.md` |

## Требования

- Claude Code
- Python 3 (только для `.docx`)
- bash (Git Bash на Windows) — для хука старта
